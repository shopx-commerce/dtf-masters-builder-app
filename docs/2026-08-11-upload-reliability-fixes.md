# Upload reliability fixes — session handoff (Aug 10–11, 2026)

Audience: any agent or developer continuing this work. Everything below is committed to `main` on GitHub (`buywitheze-droid/Anynestapplive`).

## App context (30 seconds)

- **Anynest** is a Shopify-embedded DTF gangsheet builder: React/canvas client + Express server (port 5000), test page at `/test-builder`.
- The storefront (dtfmasters.com) embeds the builder in a **cross-origin iframe** via a shell page at `/apps/dtf-builder/hot-peel`. The shell page is generated by an **external Cloudflare worker — not in this repo**. Builder iframe src: `anynest.replit.app/hot-peel`.
- Media lives on Cloudflare R2 behind `media.anynest.app` (`R2_PUBLIC_BASE_URL`, set identically in dev and production).
- The shell page implements a postMessage relay (`dtf-builder-r2-prepare/prepared/complete/completed`) that can proxy uploads through the parent page when the iframe's own network path is blocked.
- Durable engineering rules from this work: `.agents/memory/upload-relay-fallback.md` and `.agents/memory/server-upload-temp-files.md`.

## Fix 1 — Checkout upload dying cross-origin (commit `4e8ca2f`, LIVE)

**Symptom:** customer at checkout: "store upload relay did not accept the PNG (cross-origin)".
**Root cause:** the production-PNG upload tried the direct R2 route only; when iOS/Safari or a content blocker killed that fetch, there was no second path.
**Change:** `client/src/lib/r2-direct-upload.ts` — direct-upload failure now retries once through the parent shell relay. Gated on a typed `StoreApiUnreachableError` thrown by `builderFetch` for exactly the browser transport spellings (Chrome "Failed to fetch", WebKit "Load failed", Firefox `/^NetworkError\b/`). HTTP errors and mid-multipart R2 part failures rethrow (a relay retry would double-upload or mask real errors). Relay prepare in fallback mode is capped at 20s (`relayPrepareTimeoutMs`) so handler-less shells fail fast; both-fail errors surface both reasons.

## Fix 2 — Legacy upload URL routed through Shopify proxy (commit `a9e303e`, LIVE)

**Symptom:** `upload failed 500 (HTML or proxy error, not JSON) url=https://dtfmasters.com/apps/dtf-builder/api/upload-design`.
**Root cause:** the shell config still hands the builder a **legacy** upload URL, and the builder preferred it — form-POSTing whole PNGs through the Shopify app proxy, which 500s on big sheets.
**Change:** `client/src/lib/r2-direct-upload.ts` (`uploadProductionToR2`) — when a legacy URL is configured but the shell relay is available, go **relay-first**; fall back to the legacy POST only on a typed `RelayPrepareError` (prepare moves zero bytes, so rerouting is free). Post-prepare failures rethrow.
**Out of scope:** the real cleanup is the external worker no longer sending the legacy URL. Client-side ordering protects cached old shells regardless.

## Fix 3 — iOS "Failed to load images" / raw "Failed to fetch" (commit `88ec98d`, NOT yet published)

Three defects found by audit:

1. **No retry on the prepare POST.** Every raster over the 40MP inline-decode budget (i.e. any modern iPhone photo) is sent once to `/api/prepare-raster-upload` for server-side preview generation. One cellular blip or iOS killing the socket on app-switch = failed upload with a raw browser error string in the toast.
   → `client/src/lib/prepare-raster-upload.ts`: up to 3 attempts (600/1800ms backoff, fresh FormData per attempt), retrying only transport throws (three spellings above) and HTTP 502/503/504 (500 added in Fix 4). Final failure throws typed `PrepareNetworkError`.
2. **Unreachable proxy fallback on design restore.** `client/src/components/image-editor/use-restore-design-state.ts` fetched assets cross-origin with a same-origin `/api/fetch-binary` fallback gated on `!response.ok` — but a *blocked* fetch **throws**, it never returns non-ok, so the fallback was dead code for exactly its target failure (iOS CORS-cache poisoning from prior `<img>` loads). Layers silently dropped.
   → direct fetch is try/caught into the proxy. Verified the proxy allowlist accepts every host/path shape real production design states reference (`designs/`, `previews/`, `production/` on `media.anynest.app`).
3. **Raw transport strings shown to customers.** Three toast sites now map `PrepareNetworkError` to translated copy (`toast.uploadNetworkDesc`, en/es/fr). A one-byte `file.slice(0,1).arrayBuffer()` probe distinguishes "connection dropped — try again" from "iOS invalidated the picked file — select it again" (`toast.uploadFileGoneDesc`), because both surface as the same TypeError but need opposite remedies.
   Files: `upload-section.tsx`, `useImageEditorModelUploadCrop.ts` (two sites), `translations/{en,es,fr}.ts`.

## Fix 4 — "Prepare failed (500)" / production OOM kills (commit `7368c58`, NOT yet published)

**Symptom:** customer toast "Prepare failed (500)".
**Root cause (from deployment logs):** the production process was **OOM-killed** — `command finished with error [npm run start]: signal: killed`, twice within minutes, plus healthcheck-500 boot windows during which the platform answers **bare 500s** (no JSON) — exactly what the client renders as "Prepare failed (500)". Two compounding causes: multer `memoryStorage()` held every in-flight upload body (≤100MB each) in RAM, and up-to-150MP libvips decodes ran unbounded in parallel (completed prepares run 4.5–5.5s each in prod).

**Server changes (`server/routes.ts`):**
- `rasterUpload` multer → **disk storage** in an app-owned temp dir (`os.tmpdir()/anynest-raster-uploads`). Both consumers (`/api/image-info`, `/api/prepare-raster-upload`) stream from `req.file.path` and unlink in `finally`. `assertAllowedRasterFormat`/`probeAlpha`/`measureContentBounds` accept `Buffer | string`; magic-byte sniff reads leading bytes from disk.
- **Abort-safe cleanup** (architect-review finding): multer does NOT clean up when a client disconnects mid-body, and handler `finally` never runs because the handler is never reached. Temp paths are recorded the moment the storage engine names the file (custom `filename` + per-request WeakMap) and unlinked on premature `res` close (`!res.writableEnded`). Hourly age-gated reaper (1h) as defense in depth.
- **One decode at a time:** `acquirePrepareSlot()` — 1 active, FIFO queue of 8, overflow sheds `503 + Retry-After: 10` with a JSON error. Acquired after the header-only metadata/MP-cap checks, released in `finally` (idempotent). Pairs with the client retry, which treats 503 as transient.
- `sharp.cache(false)` — unique customer uploads get zero reuse from libvips' decoded-image cache; it only raised resident memory.

**Client change (`client/src/lib/prepare-raster-upload.ts`):** `500` joined the retryable statuses — platform boot windows answer bare 500s that pass within seconds; the endpoint's own deterministic rejections are 400s.

## Invariants a future agent must not break

- **Blocked `fetch()` throws — it never returns non-ok.** Any direct→proxy/relay fallback gated only on `.ok` is dead code for its main failure mode. Catch the throw and route it into the fallback.
- **Raw browser transport strings never reach customer toasts.** Map typed transport errors to translated copy at the toast site (`toast.uploadNetworkDesc` / `toast.uploadFileGoneDesc`).
- Upload-relay behavior: transport-sentinel gating only, relay prepare is the only free reroute point, legacy proxy POST is the path of last resort. Details: `.agents/memory/upload-relay-fallback.md`.
- Server upload endpoints: disk storage + abort cleanup + decode gate pattern. Details: `.agents/memory/server-upload-temp-files.md`.
